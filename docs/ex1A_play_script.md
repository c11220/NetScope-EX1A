## 分镜脚本

### 第 1 段 · 片头（0:00–0:20）

**画面**：IDE 或桌面，标题页（可选）。

**口播**：
> 老师好，我是 XXX，学号 XXX。这是《软件与系统安全》实验 1A 的演示。
> 我实现的是一个带图形界面的网络嗅探器 NetScope，使用 Python、PySide6 开发，
> 抓包通过 Npcap 也就是 Windows 上的 libpcap 完成。

### 第 2 段 · 启动与界面（0:20–1:10）

**操作**：在终端执行 `python main.py`。

**画面**：主窗口出现。

**口播**：
> 程序启动后是典型的三栏结构：上方是网卡选择与捕获控制，中间是报文列表，
> 下方是协议详情树和十六进制视图。这一布局与 Wireshark 一致，便于横向对比。
> 列表中的协议列按协议着色，一眼能看出 TCP、UDP、HTTP、TLS、DNS 的构成。

**操作**：点开网卡下拉框，选择正在上网的网卡；勾选“混杂模式”。

### 第 3 段 · 实时抓包（1:10–2:40）

**操作**：
1. 在“BPF 捕获过滤”中输入 `tcp port 80 or tcp port 443`；
2. 点击“开始捕获”；
3. 切到浏览器刷新 `http://example.com`；
4. 回到程序，展示列表滚动、状态栏的包数与速率。

**口播**：
> 这里的捕获过滤器会下发给 libpcap，编译成 BPF 程序，在**内核态**过滤，
> 只有匹配的报文才会被复制到用户态，所以高流量下也不会拖慢系统。
> 抓包回调在独立线程里只做摘要解析和入队，界面每 100 毫秒批量刷新一次，
> 这样就把高频抓包和低频重绘解耦了。状态栏可以看到实时包数、速率和丢弃计数。

### 第 4 段 · 协议详情与十六进制（2:40–3:40）

**操作**：点击“停止”，在列表中选中一条 `GET / HTTP/1.1` 报文；展开协议树；切到“十六进制”。

**口播**：
> 选中一条报文，下面会按 OSI 模型逐层展开：Frame、Ethernet II、IPv4、TCP，最后是应用层 HTTP。
> 可以看到源目 MAC、IP、TTL、TCP 序号、确认号、标志位、窗口大小等字段。
> 旁边的十六进制视图按 16 字节一行，显示偏移、十六进制和 ASCII，可以直接对照报文头。
> 为了性能，协议树不是常驻内存的，选中某一行时才用原始字节重建。

### 第 5 段 · 显示过滤器（3:40–5:00）

**操作**：依次在“显示过滤器”输入并点“应用”：
`tcp` → `http` → `dns` → `icmp or arp` → `(tcp or udp) and not port 22`。

**口播**：
> 捕获过滤是内核态的粗筛，显示过滤是用户态的精细筛选。
> 我实现的显示过滤器不是字符串包含，而是一个带优先级和括号的布尔表达式引擎：
> 先词法分析，再递归下降语法分析，最后求值，优先级是 not 高于 and 高于 or。
> 除了协议关键字，还支持字段比较，比如 `frame.len > 800`、`tcp.port == 443`、
> `http.request.method == "POST"`，以及 `contains` 子串和 `matches` 正则。

**操作**：故意输入 `http and (tcp`，展示红框与错误提示。

**口播**：
> 语法错误会实时标红，并给出具体原因，避免用户猜。

### 第 6 段 · TCP 流追踪与 HTTP 还原（5:00–6:30）

**操作**：菜单“分析 → TCP 流追踪”；选中 HTTP 流；切换“客户端→服务器 / 服务器→客户端 / HTTP 事务”。

**口播**：
> 这是本实验的加分项。流用源 IP、源端口、目的 IP、目的端口四元组归一化建键，
> 双向报文归到同一条流。每个方向按 TCP 序号缓存载荷，重组时按 seq 排序，
> 重叠片段裁剪、重复片段去重，单方向最多保留 512 KB。
> 在重组结果之上再解析 HTTP，就能把请求行、头部、响应状态码还原出来。
> 这里能看到一个 POST 登录请求，用户名和密码是明文，这也说明为什么必须使用 HTTPS。

### 第 7 段 · 统计与进程归因（6:30–7:30）

**操作**：菜单“分析 → 协议分层统计”；依次点“协议分层 / 会话 / 吞吐”。
回到主窗口，指向“进程”列。

**口播**：
> 统计页面有三部分：协议分层树按 OSI 逐级展示占比，会话表按端点对聚合包数和字节数，
> 吞吐图是按秒统计的报文数。进程列则来自 psutil 的连接快照：
> 每两秒把本地端口映射到进程，这样每条报文都能追溯到是哪个程序发出的，
> 也就能回答“某个进程产生了哪些 TCP 流”。

### 第 8 段 · pcap 保存与离线回放（7:30–8:20）

**操作**：文件 → 保存为 pcap；再打开 `demo\demo.pcap`；展示 53 条报文和已知的 HTTP/TLS/DNS。

**口播**：
> 报文可以保存为标准 pcap，也能重新打开做离线分析。
> 这份 demo.pcap 是我用脚本构造的，覆盖 ARP、DNS、TCP 握手、HTTP 请求响应、
> TLS ClientHello 的 SNI、ICMP 和 IPv6，便于复现和评分。

### 第 9 段 · 代码结构与测试（8:20–9:00）

**操作**：切到编辑器，展示 `app/core` 与 `app/ui` 目录，运行 `python -m unittest discover -s tests -v`。

**口播**：
> 代码分为 core 和 ui 两层：core 负责抓包、解析、过滤、流重组、统计和 pcap 读写，
> ui 只消费报文记录这一种数据结构，所以核心逻辑可以在没有网卡的情况下完整测试。
> 16 项单元测试全部通过，覆盖协议解析、过滤器、流重组、统计和 pcap 往返。
> 完整代码和提交历史都在 GitHub 上，链接写在报告里。

### 第 10 段 · 收尾（9:00–9:15）

**口播**：
> 以上就是实验 1A 的演示。程序实现了 NPS 抓包、NPA 协议分析、协议过滤，
> 并额外完成了 TCP 流追踪、HTTP 还原和进程归因。谢谢老师。
